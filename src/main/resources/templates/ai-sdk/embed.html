Token strategy

        

            
            

                Token endpoint recommended
                Your app exposes a route that calls POST /ai-sdk/auth/token server-side with the admin password and returns {"token":"…"} to signed-in users. The password never reaches the browser.
            

            

                Session token
                If the widget runs on a page opened after signing in here, it reuses the token from this tab's session storage. Convenient for internal tooling on the same origin.
            

            

                Password prompt
                Fallback built into the widget: on a 401 it shows a password field and calls /ai-sdk/auth/token directly. Only appropriate when every widget user is an SDK admin.
            

            
        

    


    

        
Cross-origin use

        
A frontend served from a different origin — including the Chrome extension — needs its origin allow-listed in your config:

        
ai-sdk:
  security:
    allowed-origins:
      - https://app.example.com
      - chrome-extension://<your-extension-id>
